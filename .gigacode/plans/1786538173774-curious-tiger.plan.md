# План миграции MyLLMService в ResultProjectAI

## Цель
Перенести весь функционал MyLLMService (FastAPI-сервис-прокси для GigaChat API) в проект ResultProjectAI.

## Исходный проект: /Users/ludmilagordeeva/PycharmProjects/MyLLMService

### Архитектура MyLLMService
```
MyLLMService/
├── main.py              — FastAPI entry point, инициализация сервиса
├── api/router.py        — FastAPI роуты: /health, /chat
├── llm/client.py        — GigaChat клиент с retry, timeout, executor
├── services/chat.py     — ChatService: кэширование, бизнес-логика
├── requirements.txt     — зависимости
├── .env                 — конфигурация (GIGACHAT_CREDENTIALS, SCOPE, модель)
├── cache/chat_cache.json — кэш чата на диске
└── README.md            — документация
```

### Ключевые компоненты

1. **LLMClient** (`llm/client.py`)
   - Обёртка над GigaChat SDK
   - Sync-вызовы через `asyncio.run_in_executor`
   - Retry (настраиваемый) + timeout
   - Системный + user промпт

2. **ChatService** (`services/chat.py`)
   - Business logic обработки чата
   - Кэширование повторяющихся запросов (in-memory + disk JSON)
   - Fallback-ответ при недоступности LLM

3. **API Router** (`api/router.py`)
   - `GET /health` → `{"status": "ok"}`
   - `POST /chat` → принимает `ChatRequest(message)`, возвращает `ChatResponse(reply)`
   - Dependenсy injection через `get_chat_service()`

4. **Config** (`.env`)
   - `GIGACHAT_CREDENTIALS` — base64 client_id:client_secret
   - `SCOPE` — `GIGACHAT_API_PERS`
   - `GIGACHAT_MODEL` — `GigaChat-2`
   - `LLM_TIMEOUT`, `LLM_RETRIES`

## План миграции

### Шаг 1: Структура проекта
Создать такую же структуру директорий:
```
ResultProjectAI/
├── main.py
├── api/
│   ├── __init__.py
│   └── router.py
├── llm/
│   ├── __init__.py
│   └── client.py
├── services/
│   ├── __init__.py
│   └── chat.py
├── cache/
│   └── chat_cache.json
├── requirements.txt
├── .env.example
├── .gitignore
└── README.md
```

### Шаг 2: Копирование кода
Скопировать ВСЕ файлы из MyLLMService → ResultProjectAI:
- `main.py` → обновить imports (теперь в корне)
- `api/router.py` → copy
- `llm/client.py` → copy
- `services/chat.py` → copy (содержит Pydantic модели)
- `requirements.txt` → copy
- `cache/chat_cache.json` → copy (пустой кэш)

### Шаг 3: Конфигурация
- Создать `.env.example` на основе `.env` MyLLMService (без реальных ключей)
- Обновить `.gitignore`

### Шаг 4: README.md
Скопировать и адаптировать README из MyLLMService.

### Шаг 5: Верификация
- `pip install -r requirements.txt`
- Проверить запуск: `python -m uvicorn main:app --port 8000`
- Проверить endpoint: `curl http://localhost:8000/health`
